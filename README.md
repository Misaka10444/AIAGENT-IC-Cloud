## 1 项目简介与业务场景

### 1.1 解决什么问题

职业本科学生选课时同时受五类约束限制：**先修关系、上课时间冲突、每学期学分上限、教学班容量、集中实践周次**。培养方案要求 144 学分，但由六个模块分别约束（通识必修 29、通识选修 8、专业基础 25、专业核心 41、专业选修 15、集中实践 26），模块之间不可互替。

学生通常只盯住"总学分"这一个数字，于是出现"总学分够了却毕不了业"的误判；而人工核对五类约束在 6—8 门课的组合上极易漏项。

云梯把这件事拆成两步：**先用工具算清结构化事实，再用知识库给出制度依据**，两步都留下可回溯的痕迹。

### 1.2 业务场景

场景库选题，落在「智慧校园——学业规划与选课」。系统面向人工智能工程技术专业（职业本科）在校生，覆盖四类任务：

| 任务 | 输入示例 | 系统动作 |
| --- | --- | --- |
| 学分核算 | `S001 我差多少学分` | 按六模块核算已通过/缺口，列出未通过课程 |
| 修读规划 | `S001 下学期怎么选课` | 在五类约束下求解学期方案，并解释每门课的取舍理由 |
| 资格与风险 | `S003 能毕业吗` / `S001 我会被预警吗` | 毕业五项条件逐项判定；预警等级与帮扶建议 |
| 制度问答 | `补考成绩最高记多少分` | 检索知识库，返回带文档号、章节与行号的原文片段 |

### 1.3 与教务系统的关系

云梯不是教务系统的替代品，而是它前面的一层"解释器"：教务系统回答"你能选什么"，云梯回答"你该选什么、为什么、依据在哪"。学分认定与毕业审核的最终结论仍以教务处与学院为准，每次回答末尾都带有固定声明。

## 2 环境要求与安装步骤

### 2.1 环境要求

- **Python 3.10 及以上**（开发与验证使用 3.11）
- 操作系统：Windows / macOS / Linux 均可
- **无需任何第三方运行时依赖**，`requirements.txt` 中不含第三方包
- 无网络亦可运行（默认本地确定性引擎，不发起任何外部请求）

### 2.2 安装步骤

```bash
git clone <repo-url> AIAGENT-集成电路-Cloud
cd AIAGENT-集成电路-Cloud

# 可选：创建虚拟环境
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate

# 无需 pip install，直接运行
python -m src.cli "S001 下学期怎么选课"
```

首次运行会自动构建知识库索引（7 篇文档 → 34 个片段），耗时约 20 毫秒。

## 3 配置说明

### 3.1 默认配置（推荐）

不配置任何环境变量即可完整运行。此时系统使用**本地确定性引擎**：规则路由 + BM25 检索 + 模板化生成，同一输入恒定输出，评测数字可复现。

### 3.2 可选：接入模型网关

如需把意图分类切换到语义解析，复制 `.env.example` 并填写：

```bash
export LLM_MODE=gateway
export LLM_BASE_URL=https://your-gateway.example.com/v1   # OpenAI 兼容的 /chat/completions
export LLM_API_KEY=sk-xxxx                                # 通过环境变量注入
export LLM_MODEL=your-model-id
```

**密钥获取方式**：向学校统一模型服务平台或指导教师申请，严禁将个人密钥写入代码或提交进仓库。
仓库只提供 `.env.example` 占位说明，`.gitignore` 已排除 `.env`。

网关不可用时系统自动降级回本地引擎，并在 trace 中记录 `llm_fallback` 事件，对话不中断。

### 3.3 可调参数

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `AGENT_TOP_K` | 5 | 检索返回片段数 |
| `AGENT_MIN_SCORE` | 3.5 | 相关性阈值，低于此值判为"知识库无依据" |
| `AGENT_RERANK` | 1 | 是否启用特征重排（0/1，用于消融实验） |
| `AGENT_AUDITOR` | 1 | 是否启用自检交叉校验（0/1） |
| `AGENT_SAFETY` | 1 | 是否启用输入/输出护栏（0/1） |
| `AGENT_LOG_DIR` | `./logs` | trace 落盘目录 |

## 4 运行与演示步骤

### 4.1 命令行

```bash
python -m src.cli "S001 下学期怎么选课"        # 单轮
python -m src.cli --chat                       # 多轮交互（exit 退出）
python -m src.cli --verbose "S003 能毕业吗"     # 附带工具调用与校验明细
python -m src.cli --tools                      # 打印 10 个工具的接口定义
```

### 4.2 Web 演示界面

```bash
python -m src.server.app --port 8765
# 浏览器打开 http://127.0.0.1:8765
```

界面分三栏：左侧选择学生与快捷提问，中间对话，右侧实时显示**智能体协作时间线、工具调用、自检结论、引用溯源**。

### 4.3 评测

```bash
python -m eval.run_eval --compare      # 50 条功能用例，两种配置对比
python -m eval.run_retrieval           # 25 条检索用例，重排前后对比
```

评测报告写入 `eval/report.md` 与 `eval/retrieval_report.md`。

## 5 功能清单与已知限制

### 5.1 功能清单

| 能力 | 说明 |
| --- | --- |
| 学分核算 | 六模块要求/已通过/缺口、总分缺口、未通过清单、未修核心课 |
| 修读规划 | 先修 + 冲突 + 学分上限 + 容量 + 偏好五类约束下求解，给出每门课的加入理由与被排除原因 |
| 先修校验 | 已通过=满足、在修=待确认、未修/未通过=缺失，三态区分 |
| 时间冲突 | 两两比对时隙，识别重叠节次；集中/线上课程单列为"需人工核对" |
| 毕业资格 | 五项必要条件逐项判定，输出不满足项与原因 |
| 学业预警 | 黄/橙/红三级，按"应修必修学分 − 已通过学分"的进度缺口判定 |
| 制度问答 | BM25 + 特征重排检索，返回带文档号、章节、原文行号的片段 |
| 多轮记忆 | 实体槽位（学生/课程/学期）+ 指代消解，消解过程写入 trace |
| 安全护栏 | 拦截成绩预测、代写作弊、隐私查询、篡改成绩、违法违规五类请求 |
| 可观测 | 每轮对话的完整轨迹落盘为 JSONL，可复盘、可统计 |

### 5.2 已知限制

1. **单专业覆盖**：知识库只覆盖人工智能工程技术专业 2025 版培养方案，超出范围的提问会明确弃答。
2. **数据为脱敏构造样例**：课程代码、教学班容量、学生成绩均为构造数据，结构与公开培养方案框架一致，但数值不等于真实数据。
3. **规则路由的边界**：本地引擎的意图识别依赖关键词与词典，对高度口语化或跨意图的复合提问，准确率低于语义模型；配置网关后可改善。
4. **网关模式未做真实联网联调**：请求构造、响应解析与降级链路已在本地 mock 网关上验证（`eval/test_llm_path.py`），真实网关需自行配置密钥。
5. **不替代教务系统**：所有方案与结论为建议，正式选课、学分认定与毕业审核以教务处与学院结果为准。
